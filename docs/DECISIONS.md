# Решения, принятые по ходу сборки

Одна строка — одно решение. Формат: что решено — почему.

## Стек и зависимости

- Версии: React 19.2, Vite 7.3, TypeScript 5.9, Tailwind 3.4, zod 3, msw 2, ESLint 9, Vitest 3 — выбраны стабильные мажорные ветки, совместимые с shadcn/ui, вместо самых новых (Vite 8, TS 7, Tailwind 4, zod 4, msw 3).
- React, react-dom, react-router-dom, msw, vite зафиксированы без `^` (SPEC §9.6); остальные — с `^`, версии держит `package-lock.json`.
- Добавлены `clsx`, `tailwind-merge`, `class-variance-authority` — стандартные утилиты shadcn/ui, без них компоненты shadcn не собираются.
- Добавлены `@radix-ui/react-{dialog,dropdown-menu,tooltip,tabs,popover,checkbox,slot}` — это Radix-примитивы, на которых стоят компоненты shadcn/ui.
- shadcn/ui подключён как исходники в `src/shared/ui/` (так работает shadcn), без CLI — CLI требует интерактива и сети.
- Тосты сделаны своим маленьким стором с `aria-live`, а не через `sonner` — чтобы не добавлять лишнюю зависимость.
- Селекты — нативные `<select>` в стиле shadcn: доступнее на мобильных и без лишней зависимости `@radix-ui/react-select`.
- `npm audit` показывает 4 уязвимости уровня moderate (react-router 6, vitest 3); уровня high нет, `--audit-level=high` проходит. Открытый редирект react-router закрыт собственной проверкой `safeNext()`.
- Node в контейнере — 22, CI использует Node 20 (`engines: >=20`); jsdom закреплён на ^29, потому что jsdom 30 требует Node 22+.

- Dependabot предлагает только минорные и патч-обновления одним сгруппированным PR в неделю; мажорные версии игнорируются и планируются вручную (ESLint 10 ломал `npm ci`: `eslint-plugin-react` ещё не поддерживает его).

## Окружение и сборка

- `VITE_USE_MOCKS` по умолчанию `true` (бэкенда пока нет); явное `false` отключает мок. `VITE_DEMO_MODE` по умолчанию `true` только в `npm run dev`, в сборке он включается только явно.
- `.env.*` в `.gitignore`, поэтому значения для `dev` заданы в `vite.config.ts`, а не в `.env.development`.
- `vite preview` применяет заголовки из `public/_headers` плагином; HSTS и `upgrade-insecure-requests` в preview отключены, иначе http://localhost не работает.
- E2E собирают отдельную сборку в `dist-e2e` с `VITE_DEMO_MODE=true VITE_SEED_XSS=true` и поднимают её через `vite preview` на порту 4174.
- Playwright: в контейнере используется предустановленный Chromium (`/opt/pw-browsers/chromium`), в CI — `playwright install`.

- К репозиторию подключены Cloudflare Workers Builds (а не Pages): добавлен `wrangler.jsonc` — статика из `dist`, SPA-фолбэк, сборка `npm run build`; `_headers` применяются так же. `public/_redirects` из SPEC §9.3 удалён: Workers отклоняют правило `/* /index.html 200` (ошибка 100324, «Infinite loop»), а SPA-фолбэк делает `not_found_handling: single-page-application`.

## Мок-сервер

- Состояние мок-сервера (БД и сессии) сохраняется в `sessionStorage` вкладки (`src/mocks/persist.ts`, отдельное исключение в ESLint), чтобы перезагрузка не выкидывала пользователя и не теряла изменения. Это эмуляция серверной БД, а не клиентская сессия; байты загруженных файлов не сохраняются.
- Каждая вкладка — отдельный «сервер» (MSW работает в странице); синхронизация выхода между вкладками идёт через `BroadcastChannel('mig-auth')`.
- Мок проверяет тайм-аут неактивности сессии сам (как бэкенд): 15/30 минут + 1 минута запаса.
- Для неизвестного телефона мок всё равно выдаёт `challengeId`, который никогда не подтвердится, — ответ не раскрывает, есть ли такой номер.
- Коэффициенты программ относительно «Стандарт+»: Базовая ×0,4, Стандарт ×0,7, Премиум ×2.
- Убыточность клиента хранится в seed как показатель (0,25–1,3), а не считается из 600 убытков — иначе при реальной премии все клиенты были бы ниже 15%.
- Медкарта не хранится в БД, а детерминированно генерируется из id застрахованного (МКБ-10 вымышленные сочетания).
- Изображения чеков из seed рисуются на canvas при запросе `/api/files/:id` и отдаются как PNG.
- Дополнительные эндпоинты, которых не было в SPEC §6.2: `POST /api/auth/resend`, `GET /api/dashboard/medical-access`, `GET /api/clients/:id/history`, `POST /api/clients/:id/hr-letter`, `GET /api/insured/:id/{claims,documents,access-log}`, `POST /api/insured/:id/reveal-copied` (аудит копирования), `POST /api/insured/:id/guarantee-letters`, `POST /api/claims` и `POST /api/appointments` (оператор), `GET /api/hr/employees/:id`, `POST /api/__demo/{reset,failures}` (только в демо).
- Импорт HR идёт в два шага: `POST /api/hr/employees/import` без `commit` только проверяет файл, с `?commit=1` добавляет корректные строки.
- Экспорты дополнены типами `loss_ratio`, `claims_by_category`, `premium_by_month` — для CSV по каждому графику отчётов.
- Правило «чужое не существует» реализовано через `requireOwn()`/`notFound()`: чужой ресурс — 404, отсутствие права на действие — 403.
- Реквизиты демо-аккаунтов лежат в `src/mocks/credentials.ts`; сборка без демо-режима и без моков их не содержит (проверяется тестом).

## Данные и контракт

- DTO экранов вынесены в `src/shared/types/dto.ts`; `index.ts` скопирован из SPEC §5 без изменений.
- Бизнес-правила (переходы убытков, медэкспертиза, «четыре глаза») лежат в `src/shared/domain/` и используются и UI, и моком; сервер отдаёт в `ClaimDetail` готовые `allowedTransitions` и `blockedTransitions` с причинами.
- Ответы API валидируются zod-схемами из `src/shared/api/schemas.ts`; формы и мок используют одни схемы из `src/shared/schemas/forms.ts`.
- `hrEmployeeSchema.birthDate` проверяется через `.pipe()`, чтобы некорректная дата давала ошибку поля, а не исключение.
- Даты в формах вводятся как `ДД.ММ.ГГГГ` и нормализуются схемой в ISO.

## Безопасность

- В URL попадают только статусы, id и числа (`useUrlFilters` отбрасывает остальное); строка поиска `q` живёт в состоянии компонента.
- `document.title` всегда без ПДн: «Карточка застрахованного · MIG».
- Изображения вложений загружаются `fetch` с Bearer и показываются через `blob:` URL — `<img src>` не умеет передавать токен.
- Значение `reveal` живёт только в состоянии компонента 30 секунд; `grantId` медкарты — только в состоянии компонента 15 минут, запрос медкарты с `gcTime: 0`.
- QR-токен запрашивается с `gcTime: 0` и обновляется каждые 60 секунд.
- Тест «нет демо-кода в сборке» собирает с `VITE_DEMO_MODE=false` и `VITE_USE_MOCKS=false`; `000000` ищется как отдельный токен, потому что hex-цвета вроде `#000000ff` есть в коде библиотек (qrcode).
- `javascript:`-строки в тестах и XSS-данных seed разрешены точечно (`no-script-url` выключено только для тестов, в seed — `eslint-disable-next-line` с пояснением).
- В `.gitleaks.toml` в allowlist добавлен вымышленный демо-пароль `Demo-2026!` из SPEC §2.

## UX

- Верхняя панель портала сотрудников получает хлебные крошки и главное действие от страницы через `useTopbar()`.
- Строка очереди после «Подтвердить» остаётся на месте со статусом «Подтверждена», а не исчезает; очередь показывает первые 15 задач и кнопку «Показать все».
- Приветствие на рабочем столе зависит от времени в Ташкенте: «Доброе утро / Добрый день / Добрый вечер».
- Боковая панель клиента открывается параметром `?panel=<id>` (id — допустимое значение URL), поэтому «Назад» возвращает к той же панели и фильтрам.
- Предупреждение о неактивности в HR и приложении показывается за 2 минуты до выхода (для сотрудников — на 13-й минуте, по SPEC).
- Пока открыто предупреждение о неактивности, клики вне модалки не продлевают сессию — только кнопка «Продолжить работу».
- OTP-поля не ограничены `maxLength=1`: браузерный автоввод `one-time-code` вставляет весь код в первое поле, он распределяется по ячейкам.
- «Записать к врачу» из карточки застрахованного создаёт сразу подтверждённую запись (её делает оператор).
- Роль admin видит «Клиентов» и «Клиники», но вкладка «Полисы» в карточке клиента скрыта (нет `policies.read`).
- Бухгалтер видит ФИО застрахованных, но не может открыть карточку застрахованного (маршрут закрыт по SPEC §3).
- Глобальный баннер «Нет соединения» скрыт на `/app`: там показывается свой переведённый баннер.

## HR-кабинет

- PDF-заглушки счетов и документов генерируются на клиенте латиницей (кириллица транслитерируется), чтобы не встраивать шрифт; в них нет данных сотрудников.
- Имена файлов: `invoice-YYYY-MM-DD.pdf`, `document-YYYY-MM-DD.pdf`, шаблон — `employees-template.csv`.
- В предпросмотре импорта ПИНФЛ и телефон показываются только последними 4 цифрами.
- Пример телефона в шаблоне CSV без `+`, чтобы защита от CSV-инъекций не добавляла `'`.
- «Отмена» и «Назад» возвращают на предыдущий экран, если он есть, иначе на `/hr`.
- «Напомнить всем» неактивна, если все уже в приложении; дата исключения вводится как ДД.ММ.ГГГГ, по умолчанию сегодня.
- Разрезы статистики показаны полосками, без графиков recharts — агрегатов мало, полоски читаются проще.

## Приложение застрахованного

- Пока открыт `/app`, `data-theme="client"` ставится и на `<html>`, чтобы модалки в портале Radix получали клиентские цвета.
- «Записаться сюда» передаёт клинику и специальность через `state` роутера; мастер также принимает `?clinicId=<uuid>&specialty=<enum>` с проверкой значений.
- Мастер записи показывает до 6 клиник рядом и до 8 слотов у каждой; день по умолчанию — сегодня.
- В предупреждениях о лимите категории стоят в винительном падеже («На стоматологию осталось…»).
- Повторная отправка SMS-кода — повторный вызов `/api/auth/phone` с номером из `state` роутера; номер в URL не попадает.
- Распознавание чека запускается только по первому перекодированному фото и заполняет только пустые поля.
- Ошибки zod в форме возмещения показываются переведёнными сообщениями.
- «Выйти на всех устройствах» в прототипе вызывает тот же `logout()`.
- Серверные тексты (ошибки API, причина отказа, сообщение о завершении сессии) и модалка неактивности остаются на русском и в UZ-режиме — их переведёт бэкенд.

## Тесты

- E2E-проверка API идёт через `fetch` внутри страницы: мок работает в service worker страницы, а `page.request` его обходит и попал бы на статический сервер.
- Проверка «загруженный файл без EXIF» скачивает сохранённое вложение через API под ролью оператора (переключение «Войти как…» в той же вкладке) и ищет в нём маркер `Exif` и GPS-строку.
- Проверка журнала аудита после reveal в E2E делается через «Войти как… Администратор» в той же вкладке: у другой вкладки была бы своя БД мока.
- CSP-тест ловит сообщения CSP в консоли и события `securitypolicyviolation`; редкий отказ MSW при фоновом обновлении воркера во время навигации к CSP не относится и не считается.
