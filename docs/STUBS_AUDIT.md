# Аудит заглушек перед показом

Дата: 08.10.2026. Охват: все порталы (МИГ, HR, клиника, ассистанс) и приложение застрахованного, код экранов и словари.

Что искали:
- кнопки и пункты меню без обработчика;
- элементы, которые показывают одно и то же независимо от данных;
- тексты «скоро», «в разработке», «заглушка», TODO и FIXME;
- ссылки на несуществующие маршруты;
- данные, захардкоженные в экранах, а не полученные от API.

## Итог

- **Пустых обработчиков нет.** Не нашлось ни одной кнопки с пустым обработчиком, кнопки, которая показывает только «скоро», вызова `Math.random` в экранах, TODO или FIXME.
- **Битых ссылок нет.** Каждая ссылка и каждый `navigate()` сверены с `src/app/router.tsx`, все ведут на существующие маршруты. Это подтверждает и новый e2e `e2e/nav-crawl.spec.ts`.
- **Обход навигации e2e.** Тест проходит каждый пункт боковой панели и «+ Создать» у всех 15 ролей порталов, а также вкладки и плитки приложения. Он проверяет, что нет «Страница не найдена», нет «Что-то пошло не так» и нет необработанных ошибок в браузере.

Статусы в таблице:
- **исправлено** — доделано в этом PR;
- **имитация до бэкенда** — оправданно остаётся до подключения внешней системы;
- **отдельная задача** — описано, но не делалось в этом PR;
- **по ТЗ** — так требует `docs/SPEC.md`.

## 2. Имитация до бэкенда

| Где | Что | Почему имитация | Что нужно |
| --- | --- | --- | --- |
| Вход (портал, приложение) | SMS/OTP | Код всегда `000000`, повтор через 60 с (`mocks/credentials.ts`, `mocks/handlers/auth.ts`) | SMS-шлюз |
| HR → «Пригласить», «Напомнить»; активация полиса | SMS-приглашения | Меняется только статус, SMS пишется в `smsOutbox` | SMS-шлюз |
| Подписание договоров и ДС (`documents/SigningPanel.tsx`) | E-IMZO | Сертификат строится из имени, пароль ключа не проверяется | Интеграция с E-IMZO |
| Отправка через ЭДО | Didox, Faktura.uz, Soliq | Подпись клиента появляется сама через 3 с (`mocks/lifecycle-core.ts`) | Интеграция с оператором ЭДО |
| Приложение → возмещение; МИГ → убыток | Распознавание чека | Фискальные данные вычисляются из хэша изображения (`mocks/receipts.ts`) | OCR и проверка в ОФД |
| Покрытие, подсказки, ответы справки | ИИ | Словарь синонимов и правила таблицы покрытия (`mocks/ai-provider.ts`) | Подключение модели на бэкенде |
| МИГ → «Счета и оплаты» → выписка; статус «1С» | 1С | Свой CSV из 6 колонок вместо формата обмена 1С, статус «1С ok» постоянный | Обмен с 1С |
| МИГ → рабочий стол → «Интеграции» | Статусы 1С, API клиник, MyID, Didox | Статусы фиксированные, меняется только время | Реальные проверки состояния |
| Верхняя панель портала МИГ | «MFA · VPN» | Статичный индикатор (по ТЗ, SPEC §7); MFA обязателен при входе, VPN не проверяется | Признак сети и MFA из сессии на бэкенде |
| Приложение → чат | Ответ оператора | Один из трёх шаблонных ответов через 2 с | Чат ассистанса или МИГ |
| Приложение → «Клиники рядом», запись | Расстояния | Вычисляются из id, геолокация не запрашивается | Геолокация и картографический сервис |
| Клиника → интеграции | Вебхуки партнёров | Доставка имитируется (ошибка, если в адресе есть «fail») | Реальная доставка |
| Ассистанс → «Отметить оплату» | Оплата реестра | Вводится вручную, без банка и 1С | Банк и 1С |
| Письмо HR, приглашения, отправка КП и договора | E-mail | Письмо не отправляется, учётные записи создаются с демо-паролем | Почтовый сервис |
| Все документы | Шаблоны и PDF | Шаблоны с `approved: false` и водяным знаком; «Скачать PDF» — печать страницы браузером; PDF HR и гарантийного письма собираются в браузере | Тексты МИГ и серверная генерация PDF |
| Мок-сеть | Задержки и сбои | Случайная задержка и 10% сбоев только в моке (`mocks/http.ts`) | — |
