# ТЗ: коммерческое предложение (КП) на базе генератора брошюры GOLD

Версия 1.1 · 30.09.2026 (1.1: письмо идёт после обложки брошюры). Дополняет `docs/SPEC.md`. Правила из `CLAUDE.md` действуют полностью.

## 1. Что нужно сделать

Кнопка «Подготовить КП» в портале сотрудников сейчас открывает простую форму. Вместо неё нужен полноценный процесс:

1. Андеррайтер нажимает «Подготовить КП» у клиента.
2. Открывается экран КП. Параметры уже заполнены данными клиента и полиса, справа сразу виден предпросмотр всех страниц.
3. Андеррайтер при необходимости правит цифры и сохраняет.
4. КП появляется в документах клиента: его можно открыть, скачать в PDF и отправить клиенту. После отправки КП видит HR клиента в своём кабинете.

Основа — существующий генератор брошюры GOLD. Его исходники лежат в `gold-brochure-generator/` в корне репозитория: `index.html`, `templates.js`, `fonts.css`, `assets/`.

## 2. Что за генератор (результаты разбора)

- Статическая брошюра программы ДМС GOLD: 16 страниц A4 (794×1123 px), языки `ru` и `en`, три варианта обложки: `white`, `grey`, `black`.
- `templates.js` задаёт `window.GOLD_TEMPLATES` — объект с ключами `{lang}-{variant}`. Значение каждого ключа — массив из 16 HTML-строк с inline-стилями.
- Подставляемые значения: `{{SUM}}` (страховая сумма на человека, 4 вхождения), `{{PREM_EMP}}` (премия за сотрудника), `{{PREM_FAM}}` (премия за члена семьи). Код ещё поддерживает `{{SUM_N}}` (число без валюты), его тоже оставить.
- В шаблонах нет `<script>` и `on*`-обработчиков. Картинки подключаются относительными путями `assets/img/*`, шрифты — через `fonts.css`.
- Формат сумм: для `ru` группы разрядов через неразрывный пробел и « сум», для `en` — через запятую и « UZS».
- Тексты и вёрстка брошюры согласованы и **не меняются**. Меняются только подставляемые цифры.

## 3. Структура в проекте

- Исходную папку перенеси как есть в `vendor/gold-brochure-generator/`: это эталон, его не редактировать.
- Статические файлы для работы приложения: `public/kp/gold/fonts.css` и `public/kp/gold/assets/…` (копии).
- Шаблоны: `src/features/kp/templates/gold.ts` — ES-модуль с тем же содержимым, что `GOLD_TEMPLATES`, плюс `export const GOLD_TEMPLATE_VERSION = 'GOLD 09/26'`. Сгенерируй модуль скриптом `scripts/import-gold-templates.mjs` из `vendor/…/templates.js`, чтобы при обновлении брошюры его можно было просто перезапустить.
- Реестр шаблонов: `src/features/kp/templates/index.ts` с записью `{ id: 'gold', name: 'GOLD', version, pages, languages: ['ru','en'], variants: ['white','grey','black'] }`. Позже сюда добавятся брошюры других программ.
- Страница-письмо КП: `src/features/kp/templates/offerLetter.ts` (см. §5).
- Рендер: `src/features/kp/render.ts` — **чистая функция без DOM**: `renderKp(params, ctx) → { title: string; pagesHtml: string[] }`. Её потом повторит бэкенд.

## 4. Параметры КП

```ts
export type KpVariant = 'white' | 'grey' | 'black';
export type KpLang = 'ru' | 'en';
export type KpStatus = 'draft' | 'sent' | 'revoked';

export interface KpParams {
  templateId: 'gold';
  lang: KpLang;
  variant: KpVariant;
  sumInsured: Money;          // страховая сумма на одного застрахованного
  premiumEmployee: Money;     // премия за сотрудника
  premiumFamily: Money;       // премия за члена семьи
  employees: number;          // число сотрудников
  familyMembers: number;      // число членов семей
  coverageStart: ISODate;
  coverageEnd: ISODate;
  validUntil: ISODate;        // срок действия предложения
  paymentTerms: 'single' | 'quarterly' | 'monthly';
}

export interface KpDocument {
  id: UUID;
  number: string;             // 'КП-2026-000123'
  clientId: UUID;
  clientName: string;
  policyId?: UUID;
  params: KpParams;
  templateVersion: string;    // 'GOLD 09/26' — фиксируется на момент создания
  totalPremium: Money;        // employees*premiumEmployee + familyMembers*premiumFamily
  status: KpStatus;
  createdById: UUID;
  createdByName: string;
  createdAt: ISODateTime;
  sentAt?: ISODateTime;
}
```

- `ClientDocument.kind` дополни значением `'kp'`.
- Валидация zod: все суммы — целые от 1 до 10¹², количества — целые от 0 до 100 000, `coverageEnd > coverageStart`, `validUntil ≥ сегодня`, сотрудников хотя бы 1.

## 5. Страница-письмо КП

Брошюра сама по себе не КП: в ней нет клиента, количеств и итоговой суммы. Поэтому **сразу после обложки брошюры добавляется одна страница-письмо** в её стиле. Итого КП состоит из 17 страниц в таком порядке:

1. обложка брошюры (1-я страница шаблона GOLD);
2. страница-письмо КП с данными клиента;
3–17. остальные страницы брошюры, со 2-й по 16-ю, в исходном порядке.

Порядок задаётся в одном месте — в `renderKp` (`src/features/kp/render.ts`); предпросмотр, счётчик страниц, печать в PDF и открытие сохранённых КП берут его оттуда. Сохранённые КП хранят только параметры, поэтому открываются в текущем порядке.

- Размер 794×1123 px. Письмо оформлено как внутренняя страница брошюры: шапка, поля 56 px и нижняя правовая строка — как на странице 2 шаблона (в чёрном издании графит `#3A4248` заменён на `#000000`, как во всей брошюре). Цвета: оранжевый `#E8720F`, графит `#3A4248`, песочный `#F3F1EB`.
- **Печатного номера страницы на письме нет.** Брошюра нумерует свои страницы сама, и в её текстах есть ссылки вида «на стр. 6»; номера брошюры не пересчитываются, иначе эти ссылки разойдутся.
- Содержание (RU и EN, по `lang`):
  - заголовок «Коммерческое предложение» / «Commercial offer»;
  - номер и дата, «Действительно до …»;
  - кому: организационная форма и название клиента, ИНН;
  - программа GOLD, период страхования, страховая сумма на одного застрахованного;
  - таблица расчёта: Категория | Количество | Премия за одного | Итого. Строки «Сотрудники» и «Члены семей», итоговая строка «Общая страховая премия»;
  - условия оплаты: единовременно, поквартально или помесячно;
  - контакт андеррайтера: ФИО и рабочая почта из профиля сотрудника;
  - строка «Подробные условия программы GOLD — на следующих страницах».
- В письме нет никаких персональных данных застрахованных.

## 6. Безопасность рендера

1. Любое значение, которое попадает в HTML, проходит через `escapeHtml()`. Это касается и суммы после форматирования, и названия клиента, и ФИО андеррайтера. Числа форматируются только из проверенных чисел, а не из строк.
2. КП показывается **только внутри `<iframe sandbox="allow-same-origin allow-modals" srcdoc=…>`** без `allow-scripts`. Скрипты внутри выполниться не смогут, стили брошюры не смешаются со стилями приложения. Это единственное разрешённое место вставки HTML-строк: вынеси его в компонент `src/features/kp/KpFrame.tsx` и запиши исключение в `docs/DECISIONS.md`. Правило ESLint для остального кода остаётся в силе.
3. В `srcdoc` добавь `<base href="/kp/gold/">` и `<link rel="stylesheet" href="fonts.css">`. Иначе относительные пути картинок будут считаться от адреса страницы приложения. CSP из `public/_headers` при этом не меняется: картинки, шрифты и стили грузятся с того же домена.
4. `localStorage` из исходного генератора не переносить. Параметры хранятся только в документе КП.
5. Целостность согласованных текстов: юнит-тест считает SHA-256 содержимого шаблонов и сравнивает с зафиксированным значением. Любое изменение текстов брошюры ломает тест, и его нельзя «починить» без явного обновления хэша.
6. Название документа (`<title>` iframe и имя PDF по умолчанию) формируется как `КП-2026-000123 — {название клиента}`. Спецсимволы файловой системы удаляются.

## 7. Права и аудит

| Действие | Кто |
|---|---|
| Создать, изменить черновик, отправить, отозвать КП | `underwriter` |
| Просмотр и скачивание КП клиента | роли с `clients.read` |
| Просмотр и скачивание отправленных КП своей компании | `hr` |

Добавь действия `kp.create`, `kp.send`, `kp.read` в `permissions.ts` и в матрицу тестов. В аудит пишутся события `kp_created`, `kp_sent`, `kp_revoked`, `kp_downloaded` с номером КП в `targetLabel`.

## 8. Мок-API

```
POST /api/clients/:id/kp          KpParams → KpDocument (status 'draft')
GET  /api/clients/:id/kp          → KpDocument[]
GET  /api/kp/:id                  → KpDocument
PATCH /api/kp/:id                 KpParams → KpDocument (только draft)
POST /api/kp/:id/send             → KpDocument (status 'sent')
POST /api/kp/:id/revoke           → KpDocument (status 'revoked')
POST /api/kp/:id/downloaded       → 204 (только запись в аудит)
GET  /api/clients/:id/kp-defaults → KpParams с предзаполнением (см. §9)
GET  /api/hr/documents            → дополнить отправленными КП компании
```

Мок хранит **параметры и версию шаблона**, а не PDF. Документ воспроизводится один в один. Настоящий PDF-файл появится вместе с бэкендом (§11).

## 9. Экран КП

Маршрут `/staff/clients/:clientId/kp/new?policyId=…` и `/staff/kp/:kpId` для открытия существующего.

- Все кнопки «Подготовить КП» (очередь на рабочем столе, боковая панель клиента, карточка полиса, блок «Требует внимания») ведут сюда.
- Каркас: хлебные крошки «Клиенты / {клиент} / Новое КП», справа действия «Сохранить черновик», «Сохранить и отправить клиенту», «Скачать PDF».
- Слева форма шириной 360 px:
  - шаблон (пока только GOLD), язык, обложка;
  - страховая сумма, премия за сотрудника, премия за члена семьи;
  - количество сотрудников и членов семей;
  - период страхования, срок действия предложения, условия оплаты.
- Под формой вычисляемый блок «Общая страховая премия». Там же справочная плашка (в PDF не попадает): «Текущий полис: премия X UZS, убыточность Y%».
- Предзаполнение из `kp-defaults`:
  - количество сотрудников = активные застрахованные клиента, количество членов семей = сумма `familyMembersCount`;
  - премии = текущая премия на человека по полису;
  - период = следующий год после окончания текущего полиса, срок действия = +30 дней, язык `ru`, обложка `grey`, сумма = лимит программы.
- Справа предпросмотр: страницы КП одна под другой в порядке из §5 (обложка, письмо, страницы брошюры 2–16), масштабированные под ширину колонки, со счётчиком «Страница N из 17». Обновляется при каждом изменении формы с задержкой 200 мс. Печать в PDF идёт в том же порядке.
- «Скачать PDF» вызывает `iframe.contentWindow.print()`. В `srcdoc` встроены правила печати из исходника (`@page { size: 210mm 297mm; margin: 0 }`, `print-color-adjust: exact`, разрывы страниц), так что пользователю остаётся выбрать «Сохранить как PDF». Рядом подсказка одной строкой: «В окне печати выберите „Сохранить как PDF“».
- После сохранения: тост «КП №… сохранено в документах клиента» и переход на вкладку «Документы» клиента с подсветкой новой строки.
- Отправленное или отозванное КП открывается только для чтения. Кнопка «Создать новую версию» копирует параметры в новый черновик.

**Вкладка «Документы» клиента:** КП показываются в общем списке с колонками номер, дата, программа, общая премия, статус (чип), автор. Действия: «Открыть», «Скачать PDF», «Отправить» или «Отозвать».

**Кабинет HR `/hr/documents`:** отправленные КП в блоке «Коммерческие предложения» с кнопками «Открыть» и «Скачать PDF». Черновики и отозванные КП HR не видит.

## 10. Тесты

- Юнит:
  - `renderKp`: подстановка всех плейсхолдеров во всех 6 комбинациях языка и обложки, ни одного оставшегося `{{…}}`;
  - формат сумм `ru` и `en`;
  - экранирование: название клиента `<img src=x onerror=alert(1)>` выводится текстом;
  - расчёт итоговой премии;
  - хэш шаблонов;
  - права `kp.*`.
- Компонентный: форма КП (валидация, пересчёт итога, обновление предпросмотра).
- E2E:
  1. Андеррайтер из очереди нажимает «Подготовить КП», видит предзаполненную форму и 17 страниц, сохраняет, КП появляется в документах клиента, отправляет, после чего HR этой компании видит КП в своём кабинете, а HR другой компании не видит.
  2. Оператор не видит кнопку «Подготовить КП», а прямой `POST /api/clients/:id/kp` возвращает 403.
  3. КП для XSS-клиента из seed открывается без срабатывания диалогов.
  4. «Скачать PDF» вызывает `print` у iframe (заглушка в тесте) и пишет событие в аудит.
  5. Отправленное КП нельзя изменить: `PATCH` возвращает 409.

## 11. Как это будет работать с бэкендом

Это записать в `README.md`, в код не делать:

- `POST /api/clients/:id/kp` на сервере рендерит те же шаблоны (та же подстановка и экранирование) через headless Chromium: Playwright в FastAPI или отдельный контейнер Gotenberg на своём сервере. Получается векторный PDF, он сохраняется в файловое хранилище вместе с SHA-256 файла, и документ получает `fileUrl`.
- Фронт тогда скачивает готовый файл по `GET /api/kp/:id/file`, а печать через iframe остаётся только для предпросмотра.
- Всё происходит на серверах в Узбекистане. Внешние сервисы рендеринга не используются.

## 12. Готово, когда

- Все кнопки «Подготовить КП» ведут на новый экран. Старая форма КП удалена.
- КП создаётся, сохраняется, открывается, скачивается, отправляется, и HR его видит.
- `npm run check` полностью зелёный, новые тесты из §10 проходят.
- В `docs/DECISIONS.md` записаны исключение для `KpFrame` и все прочие решения.
- В конце выведи короткий отчёт: что сделано, скриншоты экрана КП и первой страницы-письма, что упрощено.
